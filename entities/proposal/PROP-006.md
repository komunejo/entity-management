## Motivation

Every check the engine runs today is downstream of PyYAML: the linter validates the dict the parse returns, never the text the author typed. For most mistakes that is enough — a wrong type, a missing field and a dangling ref all survive the parse and get caught. But YAML has a small family of mistakes the parse itself absorbs: the text misreads *cleanly*, the dict is well-formed, and the evidence that anything went wrong is destroyed before the first check runs. [The unquoted comma is one of a class — silent misparses the parse itself hides (ISSUE-003)](../issue/ISSUE-003.md) records three verified members: a comma in a flow scalar whose tail spells a legal key, a space-`#` sequence in an unquoted scalar dropping the tail as a comment, and duplicate keys keeping the last value.

The writer-side defense exists — the YAML-pitfalls list teaches the rules to whoever writes — but knowledge at the keyboard is discipline, and [hard integrity must not depend on model discipline (REQ-004)](../requirement/REQ-004.md) is explicit about what integrity may not rest on. It rests on it doubly here, because records are edited by hand too ([documents must remain human-readable and human-editable (REQ-002)](../requirement/REQ-002.md)): no agent-side instruction reaches an editor outside a session. The mechanical half of the defense has to live in the engine.

## Sketch

- A pre-parse pass over raw text — every YAML the engine reads: schema files, record frontmatter, and the project configuration `entity-manager.yaml` — inside `validate`, run before the PyYAML parse of each file. One implementation; every existing firing point (the PostToolUse hook, conversational triggers, git pre-commit) inherits it unchanged.
- Not a parser. The pass does not understand documents; it recognizes regions and patterns — enough lexing to know whether a character sits inside quotes, inside a flow collection, or in plain text. Rewriting a YAML parser in front of PyYAML would duplicate the thing it guards.
- Seeded with one rule per verified member: an unquoted scalar inside a flow collection containing a character that is structural there (`,` `:` `#`) → ask for quotes; an unquoted scalar anywhere containing a space-`#` sequence → the tail would vanish as a comment; the same key twice in one mapping → the first value would be silently discarded.
- Duplicate keys are never admissible — there is no reading of a mapping that names a key twice where both writings were meant. Whether the engine catches them by this scan or by a stricter loader at parse time is the implementer's choice; the policy — always an error, escalated per the tiers above — is fixed here.
- One member's fix lives outside the scan: the frontmatter-truncation case (ISSUE-003's fourth member) is the engine's own `split_frontmatter` cutting on any line that strips to `---`. The fix is to tighten the splitter — a closing delimiter is only legal at column zero — after which an indented `---` stays what it is, a line of a multi-line value that PyYAML folds correctly on its own. Noted so the implementer does not over-scope the scan to compensate for a cut made one layer earlier.
- The engine is itself a writer, and must satisfy its own rules: `new <type>` interpolates the title into the stub unquoted, so the generator can plant the very members the scan hunts — a title carrying a space-`#` sequence is born truncating. Whatever the scan demands of humans and agents, the engine's emissions meet first: `new` quotes every scalar it did not author.
- The session opens with a validation, and that is what makes the tier test trivial instead of a puzzle. A flag raised at session start is by construction nobody-in-this-session's edit — inherited state, which should be rare, since every machine runs the same configuration and the same checks — and it gets the criterion protocol directly: resolvable with criterion → fix; not → ask, once, at the moment the session has the most attention to spare. From a green start, every later flag belongs to the session's own work, so "whose edit is this" never needs asking again: the answer is always "ours, just now."
- The rules do not predict how the parse would fail. They name ambiguity: this text is ambiguous to a YAML reader, and quotes cost two characters. That keeps false positives cheap — the remedy asked for is always harmless.
- The member list is open by design: a rule is added when a silent misparse is *measured*, not deduced. The Norway class (`title: yes` → boolean) stays where it is — silent at parse but visible to post-parse type validation, which already catches it.
- Diagnostic ordering: when the scan flags a line, its message replaces the downstream symptom (the phantom-key error meta-validation would have produced), so the author reads about the comma they typed, not the key they didn't.
- Who a flag interrupts is tiered, because the skill must work with the agent, not nag the human. A raised flag goes to the agent first: the likeliest cause is the agent's own involuntary slip, and the fix — quote the scalar, drop the duplicate — is one edit and a green revalidate; the human never hears of it. Only when the agent honestly cannot resolve it — the flagged text is not its own edit and it has neither knowledge nor standing to decide what the author meant — does the flag become a question to the human. Criterion includes the conversation: if the session's own context explains the flag (the human dictated the text, the agent just mistyped it, the intent was stated), the agent resolves with that and the human is not interrupted. The first tier already exists in the wiring: the PostToolUse hook returns violations on the agent's feedback channel while the offending edit is still in working memory. What the proposal adds is the second tier's discipline: a scan finding the agent cannot claim or explain is a question about intent, and intent belongs to whoever typed it.
- Jurisdiction is YAML, whole and only. The Markdown side of records has its own version of the silent-misread question, and it is split out to [raw-text scan for the Markdown side: recorded, and declined (PROP-007)](PROP-007.md) — rejected at registration, for reasons that are that proposal's to state.
