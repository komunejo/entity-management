Resolves [the ' #' rule fires on benign comments, and for typed fields its remedy is impossible (ISSUE-013)](../issue/ISSUE-013.md). The defect beneath the reported defect: the ` #` rule was designed from measured comment *styles*, never from the question of what the engine can honestly know. YAML has comments; the design question was always when a ` #` tail is decidable — and the answer changes per field, because the schema is standing right there.

**The criterion, set by the owner.** The engine covers the documented cases; the honestly undecidable ones it passes to the agent with the real ways out, and the schema is where agent and human can define such a case before checking again. A schema is never written once — it is rewritten as often as the project wants ([schema evolution is a first-class workflow (REQ-005)](../requirement/REQ-005.md)) — and everything the schema declares, the engine enforces: the engine must not silence what it knows, nor pretend to know what it cannot.

**What is decidable — and the guarantee behind the silence, stated exactly.** A trailing ` #` tail can never be part of a *legal value* of an `integer`, `number`, `boolean`, `date` or `datetime` field, of a `ref` (IDs are alphanumeric-with-dash by meta-validation), or of an `enum` whose declared values carry no `#`. That — not "every loss reds" — is what the silence promises: nothing that could have validated as content is lost without a word. When truncation leaves an illegal remainder (`count: 3 apples # nota`), the typed check downstream reds with the better message; when the tail dies beside a remainder that is still legal (`status: open # and also pending`), the tail is gone and nothing reds — but that tail could never have been the field's content, so the only thing lost is a comment or an illegality. An adversarial logical review forced this paragraph to say the weaker, true guarantee instead of the stronger, false one. The silence applies on the record surface (field kinds derived from the schema, lists taking their items' kind, the reserved `id`/`entity` fields engine-checked) and on the engine's own two surfaces, where the contract is its own documentation: schema files (`entity`, `type`, `required`, `strict`, `width`, `filename`, `prefix`, `min`, `max`, constraint `rule`/`group_by`/`fields`) and, in `entity-manager.yaml`, exactly the pair `policy.on_unresolvable`.

A `string`/`text` field with a declared `pattern` is decidable too, per instance — the owner's question ("what happens with `tag: #label     # Labels a tag`?") is what surfaced that the scan was ignoring a declaration the language has carried all along, the exact failure the criterion forbids: the engine silencing what it knows. Against the declared shape, each line answers itself: head matches and the whole does not → the tail is provably not part of a legal value → silence; the whole matches → the value legitimately contains ` #` and YAML is about to truncate it → speak; neither → the truncated value fails the pattern check downstream, which is the better red. ("Provably a comment" would overstate it: what the shape proves is legality, never intent — the distinction this record's adversarial review insisted on.) A permissive pattern (`.*`) declares that anything can be content, so it buys no silence — the declaration's power is exactly the shape's precision. What no declaration can save is the unquoted `#`-glued value itself: YAML discards it at parse, before any engine — an engine that "recovered" it from raw text would fork YAML's semantics, and this engine validates what an author's YAML says, it does not amend it (a policy about record content: normalizing its own config defaults — an absent or explicitly empty `strict` reading as the documented `true` — is the contract stating itself, not an amendment). Quotes are YAML's own mechanism there; the schema's contribution is that the red says precisely that.

What remains outside every declaration is prose without declarable shape — and that case was already legislated before this issue existed: when a value holds prose, quote it (the golden rule, and YAML's own design — the plain scalar is deliberately restricted, quoting is the spec's mechanism for text that uses its reserved sequences). The flag on unquoted prose is that rule enforcing itself, so no new schema key is needed anywhere: shaped values declare `pattern`, prose takes quotes, typed values decide themselves. A declaration whose only purpose would be to bless unquoted prose against both the rule and the format was considered and dropped.

**The backstops that make the silence honest.** Suppression is only honest if something else reds on real damage, so checks that did not exist now do: `policy.on_unresolvable` is validated against its documented values and `policy` against its documented keys (a truncated or misspelled mode — or key — must never silently mean `block`; the engine reads the key's home even though the policy itself is the agent's contract), and `strict` and `required` must be booleans (any other value was silently dead configuration, the exact phrase the engine already used for dead keys), with an explicit null — the key left empty beside a comment — meaning the documented default, never a falsy accident.

**The report's suspected narrowing, declined.** ISSUE-013 recorded a candidate: flag only values that already contain whitespace before the `#`. That is the engine guessing what it cannot know — `name: bob #smith` would go silent while being content — and with decidability doing the real work, the guess buys nothing the criterion does not already buy honestly.

**The construct the review's inventory surfaced, now flagged everywhere — and the one that was tried and withdrawn.** Asking "which cases can we imagine?" against the YAML comment rules found two silences that were never decided, only inherited. The first is the `#`-glued value (`tag: #urgente`, or the double specimen `tag: #label  # Labels a tag` — YAML reads null and both halves vanish), and it flags on *every* field kind: on an optional field the null escapes every downstream check — an adversarial review demonstrated `count: #5` validating green with its value gone under the first implementation — so the legality guarantee has nothing to stand on there. Where decidability runs out like this, the tie-break is cost, and this record states it once as the operating rule it is: **a false red is paid once and teaches its fix; a silent loss never announces itself.** That rule — not any claim that spacing reveals intent — is what draws the glued/spaced line: `key: # note`, with the space (or a `#`-run like `## …`), is the comment-after-empty-value idiom the engine's own `new` stubs emit and [DEC-020](DEC-020.md) verified legitimate — an engine that plants what its validator hunts would fail its own contract — while content-shaped-like-a-spaced-comment (`# heading` as a value) is the far rarer accident and stays, named, as the residue quoting makes expressible. The second candidate — a whole-line comment indented where a plain value's continuation would sit — was implemented and then withdrawn by the same cost rule read from the other side: the adversarial review *measured* its false reds on idiomatic, correctly-parsing YAML (a comment aligned with a list item's content), while the hazard it guarded — a continuation line beginning with `#` intended as content — remains uninstantiated by any report, and the standing rule for prose (quote it) already covers it. Measured cost against deduced hazard is no contest.

The by-name knowledge maps carry one more boundary the review forced: contract knowledge must not leak to lookalikes. Record-field kinds bind to the top level only, and `policy.on_unresolvable` binds under `policy` only, so a nested or foreign key sharing a known name keeps the ambiguous treatment instead of inheriting a silence. The schema-file map, alone, matches by name at any depth — that surface is the engine's own namespace, meta-validated loudly, with no legal place where a homonym carries a scalar the map's silence could hurt. And `policy` is validated as a namespace — unknown keys inside it are errors — because a typo'd key, like a typo'd value, must never silently mean `block`.

**The false premise, corrected where it lives.** "The remedy asked for is always harmless" was written in [PROP-006](../proposal/PROP-006.md) and implemented under [DEC-020](DEC-020.md); on typed non-string fields it was false the day it was written — quoting `3` produces a type error, and the message's own advice moved a project from one red to another. Both records carry the correction in place, visibly, per [a record that is wrong is corrected in place, and the correction names the error (DEC-019)](DEC-019.md).

**Untouched.** The flow-collection rules (the comma family, measured in [ISSUE-003](../issue/ISSUE-003.md)) are out of this decision's scope: inside `{...}` and `[...]` a ` #` genuinely truncates or breaks the line, and the flag there was honest all along.

Verified before release, twice — once by the implementing session, once by an adversarial review instructed to break it (whose five verified findings — the optional-typed glued silence, the null-`strict` inversion, the homonym-key leak, the idiomatic-list false red, the policy-key typo — each produced a correction recorded above): the reporter's three cases green (config `on_unresolvable: block # comment`, `count: 3 # nota`, spaced-comment stubs); real truncations red through the typed checks, with the scan's message correctly replaced by the better one; the glued flag firing on every kind and silent on the idiom; the pattern cases in all three directions (shaped value plus comment green, glued value flagged, truncated value red through the pattern check); idiomatic list-item comments green; this repository green, and both `filename: free` fixture projects (prose names, Spanish diacritics) green; the engine's own `new` stub passing the engine's own scan.
