References use IDs like `DEC-002`, never names or titles: renames are the great destroyer of coherence in Markdown projects. Each entity type declares a unique prefix, so any ID is self-describing about its type. Typed frontmatter refs (`supersedes: DEC-001`) and inline prose refs (`[one file per entity — YAML frontmatter is the record, prose is the body (DEC-001)](DEC-001.md)`) are both validated by the engine — see [the validation engine is generic and stable; schemas are data (DEC-002)](DEC-002.md).

The illustration above shows the prose-reference form of its era, and this record has now had two eras. As first written it showed no prose form at all (none existed yet — 0.5.0 introduced one); the 0.7.0 migration then modernized the example to the current single-link form. The superseded intermediate form, kept here so the error is not repeated by whoever finds old records or old muscle memory:

```
[one file per entity — YAML frontmatter is the record, prose is the body](DEC-001.md)^[DEC-001](DEC-001.md)
```

That caret construct (0.5.0–0.7.0) imitated a footnote mark and broke in footnote-aware renderers; [a prose reference is one link whose text carries the ID (DEC-022)](DEC-022.md) superseded it.
