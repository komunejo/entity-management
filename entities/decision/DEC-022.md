Supersedes [references in prose are ordinary Markdown links by default; wikilinks are opt-in (DEC-017)](DEC-017.md), resolving [the reference annotation imitates a footnote mark, and footnote-aware renderers take it at its word (ISSUE-012)](../issue/ISSUE-012.md). DEC-017 was considered correct and was implemented; it is superseded because a better solution was found. The caret construct it chose was born of a misremembered footnote syntax and shatters in Pandoc, which owns `^[...]` as an inline footnote. Everything else DEC-017 decided — Markdown links as the default, wikilinks opt-in, the label free, every part of a reference recoverable from the ID — was never in question and is carried forward by this decision.

The corrected form is a single ordinary Markdown link whose text carries the ID:

```
[contract changes are never silent (REQ-006)](../requirement/REQ-006.md)
[REQ-006](../requirement/REQ-006.md)
```

The second is not a second form: it is the first with no label, which is why the grammar is one rule. A link's text that is exactly an ID, or ends with the ID in parentheses, marks the link as an entity reference — provided the ID's prefix belongs to a declared entity type. The engine validates that the ID resolves and that the destination, resolved against the referring record's own directory, is that ID's file. A label that merely repeats its own ID (`ID (ID)`) is flagged as redundant: in an ID-heavy space that redundancy would metastasize, and the bare form is what it collapses to.

What the one-link form buys over the two-link constructs considered and rejected (academic-citation pair, true footnotes, reference-style definitions): the path is written once instead of twice, so hand-editing has one destination to maintain instead of two to keep agreeing; the raw line is half as long, which matters in the editors these records are worked in; and the labeled form degenerates into the bare form by removing the label, instead of by switching constructs — the collision ISSUE-012's second face names is dissolved by the grammar rather than legislated around.

Two boundaries the choice draws, stated so nobody rediscovers them:

**An ID-shaped text under an undeclared prefix is an ordinary link.** `[ISO-9001](https://...)` in a project that declares no ISO prefix is prose, and the engine has no opinion — DEC-017's guarantee that plain links stay untouched survives. The cost is that a typo in the prefix itself (`RQE-006`) goes silent instead of red; the prefix vocabulary of a project is small and stable, and the alternative — flagging every ID-shaped link text on the page — would put the engine's opinion on prose it was told to leave alone.

**The label is free except for its tail.** A label that legitimately ends in a declared-prefix `(ID)` without meaning a reference will validate red until rephrased. That is a false red — the failure this project has repeatedly chosen as the safe one — and the rephrasing is always available, because the parenthesized ID tail is exactly the convention this decision reserves.

Measured rather than assumed, this time on the class and not the sample — the confusion DEC-019 warns about arrived through DEC-017's "measured on the renderer this repository is published through," one renderer presented as a property of all of them. The corrected form renders identically ("label (ID)", one live link) in mistletoe 1.6.0 (MarkPub/vitrine's parser) and Pandoc 3.7.0.2 — HTML and docx conversion both: visible text intact, hyperlink targets correct in the document's own XML — and is core CommonMark, owned by no extension. Measured equally in a free-filename project (prose names carrying spaces, commas and parentheses; labels with accents and internal parentheses; cross-type references), which is where the caret-era validator was found to skip angle-bracketed destinations containing parentheses without a word — a false green, fixed with this decision's implementation. The legacy caret form, measured in Pandoc, becomes an inline footnote plus the annotation path leaked as literal prose — every reference in a registry converted to PDF or docx would have carried that. True footnote syntax (`[^ID]`) was measured too and rejected on the same evidence: mistletoe renders it as a dead link, and where footnotes do work the marker is renumbered sequentially, so the ID this project wants visible is exactly what the reader loses. The engine now names the legacy caret when it sees one outside fenced code, so the form cannot creep back in through habit; historical specimens inside fences stay as they were written.
