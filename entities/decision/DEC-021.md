Implements [state the requirements, don't ship them: install guidance at household scale (PROP-008)](../proposal/PROP-008.md), resolving [the documented install path fails on an externally-managed Python (ISSUE-002)](../issue/ISSUE-002.md). The decisions the implementation settled, including the proposal's two open questions:

**The missing-dependency message points only at targets that travel.** The engine is distributed as the skill folder; the repository's README and `docs/troubleshooting.md` do not travel with it, so the message names no repo paths. It addresses its two possible readers in turn — the agent (set PyYAML up as ordinary environment work: per-user, only if missing, never elevated; an own virtual environment always works) and the human (your assistant can arrange it, or install it any way you prefer) — and the only pointer it carries is the library's official page. No `pip install` recipe: the single-command remedy was the original defect, aiming one platform's answer at every platform and at the wrong actor.

**The Python floor is checked before the dependency.** The script verifies ≥ 3.8 before importing anything and exits 2 with a version message naming python.org — a plain sentence, not a stack trace, on interpreters old enough to have produced one.

**SKILL.md gains a Runtime section addressed to the agent.** Verify the interpreter is real before invoking it (the Windows Store decoy has no version; on macOS `xcode-select -p` detects the Command Line Tools without triggering their GUI dialog, which would hang a non-interactive run). Obtain PyYAML per the machine's own conventions under two absolutes — per-user scope, only if missing. When no usable Python exists (typically Windows), ask the human for exactly one thing, in plain words, and wait: to an almost-ignorant user, a scary message is an engine defect of the same rank as a false red.

**Hooks invoke the interpreter that satisfies the runtime.** `references/hooks.md` now says so: a hook calling a bare `python3` while PyYAML lives in the project's virtual environment dies at exit 2 on every firing.

**The runtime is a triage family with an owner.** `references/troubleshooting.md` files exit-2 runtime failures under the agent's own: a missing PyYAML is housekeeping resolved silently, a hook failing where the hand run works means the hook's interpreter, and the sole escalation is the no-Python machine — the protocol's one plain ask. The flow the skill teaches lets most agents obtain PyYAML without troubling their principals at all; the meticulous self-managing human keeps every install style open. Observed in use after the design landed (on macOS, presumably identical on Windows) and confirmed by the platform's own documentation: Claude's desktop environments run the agent's work in an isolated environment of its own, so the most frequent case satisfies the runtime entirely inside it and the escalation is left to agents operating directly on a host. What that environment provides is referenced (the Claude Help Center), never replicated — the stated-not-shipped principle applied to platform facts as well as dependencies.

**[DEC-003](DEC-003.md) stands as written, with its reading fixed here**: "PyYAML as the only dependency" means the only *stated requirement* — never a copy the engine carries or fetches. Vendoring (unowned copies rot), a homegrown subset parser (reinventing a maintained wheel), and download-on-first-use (a downloader of our own, failing cryptically for the least equipped user) are recorded as paths not taken in the proposal.

**Humans get their own door**: `docs/troubleshooting.md` opens with the two pre-engine failure stories — no usable Python, Python without PyYAML — each ending in official sources rather than a recipe that pretends one command fits every machine; the README states the two requirements once, gently, with the same pointers.
