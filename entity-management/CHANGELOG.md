# entity-management skill changelog

The engine and skill evolve by versioned maintenance, never by per-project regeneration (DEC-002). Every engine or skill change gets an entry here, mirroring the discipline that schemas/CHANGELOG.md imposes on schemas (REQ-006).

## 0.7.1 — 2026-07-27

- Engine fix: the pre-parse ` #` rule no longer fires on trailing comments the schema makes decidable. On fields typed `integer`, `number`, `boolean`, `date`, `datetime`, `enum` (values without `#`) or `ref` — and on the engine's own contract keys in schema files and `entity-manager.yaml` — the tail could never be part of a legal value: the scan is silent, and a truncation that damages the value leaves an illegal remainder the typed check downstream reds with the better message. Before, correct configuration went red on upgrade and the message's remedy (quote it) produced the next red on typed fields — the false premise ("the remedy is always harmless") is corrected in place in PROP-006 and DEC-020 (ISSUE-013, DEC-023).
- Engine: a `string`/`text` field's declared `pattern` — a declaration the scan had been ignoring — now decides comment tails per instance: value matches the shape and the whole line does not → provably a comment, silent; the whole line matches → the value legitimately contains ` #` and YAML would truncate it → flagged; neither → the truncated value fails the pattern check downstream, the better red. A permissive pattern (`.*`) buys no silence. Shapeless prose keeps the flag, and prose was already legislated: when a value holds prose, quote it. No new schema key — the language already had the vehicle.
- Engine: the `#`-glued value is now flagged on **every** field kind (`tag: #urgent`, `count: #5` — a hashtag or commented-out value to a human, a comment to YAML: the field parses to null and the text is gone, and the null escapes every downstream check, so no silence is honest there). The message names the remedy the field actually has — quotes where it holds text, the real value where the type could never contain `#…`. The spaced idiom (`key: # note`, `## …`) stays legitimate, as the engine's own stubs emit it. Field-kind knowledge never leaks to lookalikes: record-field kinds bind to the top level, `policy.on_unresolvable` binds under `policy` — a nested key sharing a known name keeps the ambiguous treatment.
- Engine: declared settings are no longer half-read — `policy.on_unresolvable` is validated against its two documented modes and `policy` against its documented key names (a typo in value or key must never silently mean `block`), and `strict`/`required` must be real booleans (anything else was read as merely truthy: silently dead configuration, now loud), with an explicit null — the key left empty beside a comment — meaning the documented default, never a falsy accident.
- Verification: the design survived a second, adversarial review instructed to break it; its five verified findings (optional-typed glued silence, null-`strict` inversion, homonym-key leak, a false red on idiomatic list comments from a candidate rule that was then withdrawn, policy-key typo) are each corrected above and recorded in DEC-023.
- Docs, agent layer: the comment rules' calibration in the schema language reference (YAML pitfalls, project configuration, field spec, design guidance), plus a new appendix — `references/comment-decidability.md`: what the engine knows and from where, the agent's three routes on a comment flag (quote prose / propose `pattern` where values have shape / one intent question), and the YAML frontier no declaration crosses. Triage points at it; SKILL.md now instructs agents to read the changelog delta after any skill upgrade — the changelog is where contract changes speak to the agent.
- Docs, human layer, rebuilt: `docs/troubleshooting.md` becomes `docs/troubleshooting/` — nine pages by error family behind an index that maps every message the engine can emit to the page explaining it. The catalog roughly doubles, because the messages raised while *authoring a schema or the project configuration* were absent from it — the half an adopter meets first, and meets alone. Three entries were corrected rather than moved: one described a rule the adversarial review had withdrawn, one scoped the `#`-glued flag to free-string fields when it now fires on every kind with a different remedy per kind, and the policy entry predated key-name validation. The register was levelled throughout: the guide presupposes no YAML and no regular expressions, teaching each mechanism where it is needed.
- Docs, human layer: `docs/adopting.md` (new) — the page between “what is this” and “something went red”: what a record and a schema are, what adopting asks (a structure gets declared, and the engine validates against that declaration rather than inferring one — where the declaration comes from, and how much of it an agent drafts alone, is the owner's arrangement to make), when the honest answer is not to adopt, and the two ways in. It is also where a human meets this version's `pattern` gain in the terms that matter to them: declaring a field's shape both checks it and buys silence from the comment scan — the engine can only check what you declare, and only pesters you about what you left undeclared. It exists because every field report of a struggling adoption reduces to that one misread, and the doctrine answering it lived only inside an incident record (PROP-011, ISSUE-015).
- Docs, human layer: `docs/quick-guide.md` and `docs/schemas.md` (both new) close the gap the other two left between them. The walkthrough runs from an empty folder to a validated record with the engine's real output — including the first red, which arrives on day one by design — and states the order that decides a migration: convert ten, revise the schema, then the rest. The schema page is the language explained for a person writing their own, so that a second type does not require reading a specification addressed to agents; it is explicitly non-normative, and says so, since two sources of truth is the drift this project exists to prevent.
- Docs: the README shows a record and a schema instead of only describing them, states the adoption cost beside the integrity claim, and no longer contradicts its own “no technical setup required” six lines later; the runtime requirements stay stated once, gently, with official pointers (DEC-021).
- Docs, agent layer: SKILL.md's initialization workflow now opens with the adoption decision — name the recurring kinds, state the cost, and say when the answer is no or partial, rather than assuming every corpus in reach is a candidate registry.
- Registry: ISSUE-013 resolved by DEC-023. PROP-011 is implemented by the documentation layer above, and the absolutist reading of the declaration doctrine its motivation had stated — "never deduced from the data", a case turned into a law — is corrected inside the record rather than quietly rewritten (DEC-019).
- Skill, working guidance while ISSUE-017 stands: when the agent picks a filename it keeps parentheses out of it, and angle-brackets any destination that has them. Bounded deliberately — it governs names the agent chooses, never a rename of a project's existing files to accommodate an engine limitation, and in a `filename: free` project whose corpus already carries such names the instruction is to say so and write every reference angle-bracketed instead of proposing a mass rename. `new` needed no change: it suggests the bare ID path and never derives a filename from a title.
- Docs, both layers: the angle-bracket rule for link destinations is stated where it is needed and for the right reason. A destination holding **spaces** validates but renders as literal text in many renderers; a destination holding **parentheses** is not recognized as a reference at all — invisible rather than broken, and stricter than CommonMark, which allows balanced parens bare. The human guide gains the rule it never carried, the agent reference had it for spaces only and as a rendering matter, and the schema page no longer tells a `filename: free` project that the engine has no opinion about names. The engine is unchanged: every destination it writes has been angle-bracketed all along. Registered as ISSUE-017, where the measurement, the provenance (present since the prose form arrived in 0.5.0; 0.7.0 added the angle-bracketed escape without closing the gap) and the reason the fix belongs with the reference-grammar work of ISSUE-014 are set out.
- Registry: ISSUE-016 opens the silence this release documents as known — the engine reads the values of the two config keys it recognizes, and `policy`'s keys and value, but says nothing about a top-level key it does not recognize. A misspelled `schemas_dir:` falls back to the default, and where that default folder exists beside the intended one the run reports green having validated the wrong corpus. Found while inventorying every message the engine can emit for the guide; the fix is engine work and is not in this release, so both audiences are told where the silence is instead — humans in the configuration page, agents in the schema language reference, which is the layer that travels with the skill.

## 0.7.0 — 2026-07-26

- Engine, breaking: the prose reference form is now one Markdown link whose text carries the ID — `[label (ID)](path)`, bare `[ID](path)` when unlabeled. The 0.5.0 caret construct (`[label](path)^[ID](path)`) imitated a footnote mark no dialect owns; Pandoc reads `^[…]` as an inline footnote and the construct shatters in any footnote-aware renderer (ISSUE-012, DEC-022 correcting DEC-017). The legacy caret is recognized outside fenced code only to be named as an error, so it cannot creep back. An ID-shaped link text under a prefix no schema declares stays an ordinary link; a label that merely repeats its own ID is flagged as redundant (the bare form is what it collapses to).
- Engine: `new` stubs hint the corrected reference form.
- Engine fix: the reference pattern now reads angle-bracketed destinations containing parentheses — `[label (ID)](<a name (draft).md>)` — the very form `index --write` emits for free filenames. Before, such a link matched nothing and was silently not validated: a false green in every `filename: free` project whose names carry parentheses, latent since 0.5.0. Measured in a scratch project with prose filenames (spaces, commas, parentheses), varied labels (accents, internal parentheses, cross-type), and Pandoc HTML/docx transformation of the results.
- Docs: the reference form updated in SKILL.md, the schema language reference, and `docs/troubleshooting.md`, which gains entries for the redundant-label and legacy-caret errors and loses the two-destinations one (the corrected form has a single destination).
- Registry: all records migrated in one pass — 34 files, with the 7 label-equals-ID references collapsed to the bare form; fenced historical specimens left as written.

## 0.6.1 — 2026-07-26

- Engine: the missing-PyYAML message no longer prescribes `pip install pyyaml` — the command half the current platforms reject, aimed at an actor (the agent) that neither has nor should have the permissions it assumes. It now addresses both possible readers in plain words: the agent (obtain the library as ordinary environment work — per-user, only if missing, never elevated) and the human (your assistant can arrange it; official page as the only pointer). The Python floor (≥ 3.8) is checked before any import and fails as a sentence, not a stack trace (ISSUE-002, PROP-008, DEC-021).
- Docs: SKILL.md gains a Runtime section addressed to the agent — verify the interpreter is real before invoking it (Windows Store decoy, macOS Command Line Tools dialog), obtain PyYAML per the machine's own conventions (a platform-provided agent environment, e.g. Claude Cowork's, satisfies the runtime inside itself — the platform's documentation, referenced not replicated, states what it provides), and only when operating directly on a host with no Python ask the human for exactly one thing in plain words. `references/troubleshooting.md` files exit-2 runtime failures as a triage family owned by the agent (missing PyYAML is silent housekeeping; the no-Python machine is the protocol's one plain ask). `references/hooks.md`: hooks must invoke the interpreter that satisfies the runtime, not a bare `python3`. README states the two requirements once, gently, with pointers to the official sources; `docs/troubleshooting.md` opens with the two pre-engine failure messages, quoted as the engine emits them, explained for humans.

## 0.6.0 — 2026-07-26

- Engine: pre-parse raw-text scan over every YAML the engine reads (config, schema files, record frontmatter), run before PyYAML — catching the family of misparses that destroy their own evidence: a multi-word unquoted scalar inside a flow collection (an unnoticed comma splits it into extra keys, silently when the tail spells a legal one), and an unquoted value containing ` #` (the tail vanishes as a comment). Scan findings replace the downstream symptom, so the author reads about the comma they typed, not the phantom key they didn't (ISSUE-003, PROP-006).
- Engine: duplicate keys in any mapping are rejected with the line number, at any depth — PyYAML's default keeps the last value and silently discards the rest (PROP-006: never admissible).
- Engine fix: the frontmatter closing delimiter is only accepted at column zero. An indented `---` inside a multi-line value was previously taken as the close, truncating the frontmatter before the parse — fields below the cut fell silently into the document body (ISSUE-003's fourth member).
- Engine fix: `new` emits the title double-quoted — the engine's own emissions meet the scan's rules (an unquoted title carrying ` #` or a comma was born misparsing).
- Hooks: session-start validation added as a firing point (SessionStart hook), making flag ownership trivial — from a green start, every later flag belongs to the session's own work. Pre-commit reframed as the layer covering hand edits made with no agent at the keyboard.
- Docs: `references/troubleshooting.md` (new) — the agent's flag-triage discipline: claim, resolve with criterion, escalate at most one intent question; criteria the human's answers establish are recorded so no question is asked twice. The human-facing companion, `docs/troubleshooting.md` in the repository, explains every engine message with examples (repo documentation, not packaged).
- Docs: the YAML-pitfalls list gains the silent-misparse family and the writer-side rule that avoids it — when a value holds prose, quote it — in the schema language reference, SKILL.md's record-creation and bulk-import workflows, and the golden rule (which now also carries the escalation protocol in brief).

## 0.5.0 — 2026-07-15

- Engine: prose references in the form `[label](path)^[ID](path)` are validated — the ID resolves, the two destinations agree, and they point at that ID's file relative to the record making the reference. The label is never read; it is free, and a stale one is soft integrity (DEC-017). A Markdown link without the `^[ID](path)` annotation is an ordinary link and is untouched. `[[ID]]` remains valid and is still checked for its ID.
- Engine: optional per-schema `filename` — `prefixed` (the default, `<ID>.md` or `<ID>-<handle>.md`) or `free` (unconstrained; the id lives in the frontmatter alone). A project whose records are named in prose declares `free` and keeps its names (DEC-018).
- Engine fix: the `prefixed` check tested `startswith`, so `PROP-0011.md` passed as a name for `PROP-001`. It now requires the ID exactly, or the ID followed by `-`.
- Engine fix: `index --write` wraps destinations containing whitespace or parentheses in angle brackets. Unescaped, they rendered as plain text — a generated index of dead links, which `free` filenames would have hit immediately.
- Engine: `new` suggests `<ID>.md` and no longer slugifies the title into a filename. A handle is chosen, never derived (DEC-018).
- Docs: the Markdown reference form documented as the default in SKILL.md and the schema language reference; the filename described as an ID plus an optional handle; the rename workflow no longer offers to leave a slug stale.

## 0.4.1 — 2026-07-15

- Engine fix (DEC-014): `index --write` no longer forces the interpreter's platform line ending on the file it writes. It now preserves the line endings of an existing index and defaults to LF for a new one; the endings are detected from the raw bytes, since universal-newline translation on read would hide them. On Windows the previous behaviour rewrote every line of an LF index as CRLF, so each regeneration produced a whole-file diff and silently converted the file. `index --write` is the engine's only file write; `new` prints to stdout and is unaffected. Validation, schema handling and the CLI surface are untouched.

## 0.4.0 — 2026-07-12

- Engine: `index --write` computes every link relative to the index file's own location (stdout falls back to the project root), so the index works at any path the project prefers (DEC-012).
- Engine: folder notes are never records — a Markdown file named exactly like its own directory (`entities/entities.md`, `registry/skill/skill.md`) is skipped by record discovery, letting the generated index live as the registry's folder note in vault projects; the exemption is exact-name-only and stray detection is otherwise unchanged (DEC-012).
- Engine: optional per-schema `path` (project-root-relative, no `..`, unique, non-nesting) places a type's records anywhere in the project, overriding `<entities_dir>/<dir>`; record discovery scans declared locations, `new` suggests the declared home, and the default layout needs no declaration (DEC-013).
- Docs: `path`, the folder-note exemption, and free index placement documented in the schema language reference and SKILL.md.
